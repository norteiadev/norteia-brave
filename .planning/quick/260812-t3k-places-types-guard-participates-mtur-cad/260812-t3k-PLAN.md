<task type="auto" tdd="true">
  <name>Task 1: reject geographic entities in the Places match</name>
  <files>brave/lanes/atrativos/places_enrichment.py, tests/unit/lanes/test_places_enrichment.py</files>
  <behavior>
    - A candidate whose `types` contains `political` is skipped by `_best_match` even at name
      score 100 and distance 0.
    - A lower-scoring real POI in the same result set still wins.
    - A `beach`/`natural_feature` POI is NOT rejected.
    - No candidate left → the lane keeps the TA floor (existing behaviour, unchanged).
  </behavior>
  <action>
Add a module constant and a guard clause in `_best_match`.

Evidence (docs/poc/places-extra-fields-spike.auto.raw.json, 15 atrativos, separação 15/15):
the three broken matches carried `political`; the twelve good ones did not. `political` is
Google's own marker for an administrative/geographic entity, so it also covers geographic
types we have not seen yet — a deny-list on `locality`/`neighborhood`/`sublocality_level_1`
alone would not.

`beach` is deliberately NOT rejected: Praia de Camburi resolved to
`["beach","natural_feature","establishment"]` and DID return `editorialSummary`.

The alternative rule ("require `establishment`") separates the same 15/15 but fails CLOSED —
if Google ever stops emitting the legacy `establishment` type, every atrativo silently stops
being enriched. `political` fails OPEN (today's behaviour), so the blast radius of a taxonomy
change is bounded.
  </action>
  <verify>
    <automated>.venv/bin/python -m pytest tests/unit/lanes/test_places_enrichment.py -q</automated>
  </verify>
  <done>
- New tests cover: political rejected, real POI wins over political, beach kept.
- Full `tests/unit/lanes/test_places_enrichment.py` still green.
  </done>
</task>
